# From LVGL MPY Studio to Copper and Code Studio

Up to 0.7 the product was called LVGL MPY Studio. Its name began with the name of somebody
else's project, so it got one of its own: **Copper and Code Studio**, a visual GUI builder for
MicroPython and LVGL. LVGL and MicroPython are still what it is for.

## What a user has to do

Nothing. On the first start under the new name the IDE copies, once, what the old one kept:

- the settings (language, window layout, recent files), from `LVGL MPY Studio` or, for those who
  come from 0.4, from `LVGL IDE`;
- the configuration folder, with imported boards, the MCP switch and the backups of `main.py`
  made by Install Autostart: `~/.config/lvgl-mpy-studio/` is copied to
  `~/.config/copper-and-code-studio/` (on Windows under `%APPDATA%` when it was there).

The old settings and folder are left in place, so an earlier version still finds them. Projects
are not touched: their format did not change.

## What changed

| What | Before | Now |
|---|---|---|
| Command | `lvgl-mpy-studio` | `copper-and-code-studio`; `lvgl-mpy-studio` and `lvgl-ide` still work |
| Python distribution | `lvgl-mpy-studio` | `copper-and-code-studio` |
| Linux package | `LVGL_MPY_STUDIO-x86_64.AppImage` | `Copper_and_Code_Studio-x86_64.AppImage` |
| Windows program | `LVGL_MPY_STUDIO.exe`, `…-Setup-win64.exe`, `…-portable-win64.zip` | the same with `Copper_and_Code_Studio` |
| MCP server name (`serverInfo`) | `lvgl-mpy-studio` | `copper-and-code-studio` |
| Environment variable for the Windows C toolchain | `LVGL_MPY_STUDIO_TOOLCHAIN` | `LMS_TOOLCHAIN`; the old name is still read |
| Environment variable for another `mpremote` | `LVGL_MPY_STUDIO_MPREMOTE` | `LMS_MPREMOTE`; the old name is still read |
| Marker of a folder written by **Build for the Web** | `.lvgl-mpy-studio-web` | `.copper-and-code-studio-web`; a folder with the old one is still replaced |
| Address of the IDE in the browser | `copper-and-code.github.io/lvgl-mpy-studio-web/` | [copper-and-code.github.io/copper-and-code-studio-web/](https://copper-and-code.github.io/copper-and-code-studio-web/); an app installed from the old address is installed again from the new one, and keeps its projects and settings |
| Include guards of the exported C header files | `LVGL_MPY_STUDIO_UI_H`, `LVGL_MPY_STUDIO_UI_EVENTS_H` | `LMS_UI_H`, `LMS_UI_EVENTS_H` |
| Windows taskbar identity | `CopperAndCode.LvglMpyStudio` | `CopperAndCode.CopperAndCodeStudio`: a pinned icon is pinned again once |

The Windows installer keeps its identity: it upgrades an installation of LVGL MPY Studio in its
folder and removes the old program and shortcuts, instead of installing a second program.

An MCP client configured for an earlier version keeps working, because the old command is still
there. Exported C sources regenerated by this version differ from the earlier ones in the include
guards only.

## Lines on the board

The IDE runs short scripts on a board and finds the answer in what they print by a marker at the
start of a line. The markers began with `LVGL_MPY_STUDIO_` and now begin with `LMS_`, the prefix
already used for everything the IDE puts on a board (`/lms_apps`, `lms_sandbox.py`,
`LMS_AUTOSTART_V2`). The scripts are sent by the IDE each time, so a board needs nothing new.

| Before | Now | Printed by |
|---|---|---|
| `LVGL_MPY_STUDIO_INFO=` | `LMS_INFO=` | the probe of a board on connect |
| `LVGL_MPY_STUDIO_IDENTITY=` | `LMS_IDENTITY=` | the identity of a board, for its autostart backups |
| `LVGL_MPY_STUDIO_FILE=` | `LMS_FILE=` | the read of a file |
| `LVGL_MPY_STUDIO_SIZES=` | `LMS_SIZES=` | the check of an upload |
| `LVGL_MPY_STUDIO_FREE=` | `LMS_FREE=` | the free space before a write |
| `LVGL_MPY_STUDIO_DONE=1` | `LMS_DONE=1` | a write or a delete that worked |
| `LVGL_MPY_STUDIO_LIST=` | `LMS_LIST=` | the list of a folder |
| `LVGL_MPY_STUDIO_STOPPED` | `LMS_STOPPED` | Stop |
| `LVGL_MPY_STUDIO_CHUNK=`, `LVGL_MPY_STUDIO_EOF=1` | `LMS_CHUNK=`, `LMS_EOF=1` | the download of a file over a UART console |
| `LVGL_MPY_STUDIO_LIVE_OK`, `LVGL_MPY_STUDIO_LIVE_FAILED` | `LMS_LIVE_OK`, `LMS_LIVE_FAILED` | live update |
| `LVGL_MPY_STUDIO_APP_READY` | `LMS_APP_READY` | an application, when it has started (read by no one in the IDE) |

An application installed on a board by an earlier version still prints
`LVGL_MPY_STUDIO_APP_READY` until it is uploaded again. Whoever reads these lines from another
program, such as a test bench, uses the new names.

## What did not change

- Everything on a board and in a project: the `lms` names, `/lms_apps`, the project format and its
  version, board profiles, block manifests, the `// <lms:new-handlers>` markers in exported C.
- The names of the release files of the browser runtimes, `lms-web-runtime-v*.zip` and
  `lms-mpy-cross-v*.zip`.
- The history: earlier entries of the changelog and [How it was built](how-it-was-built.md) use
  the name of their time.
